Auditoría de seguridad

Estado técnico, controles implementados y residuales opcionales

3 de agosto de 2026 · Revisión de código y configuración · Commit 0121a987 · Producción: courtmanagerpro-umber.vercel.app

Veredicto para TI: el sistema alcanza un nivel profesional / muy bueno para un SaaS de gestión de utilería deportiva. Es adecuado para piloto controlado y uso diario en producción con datos reales. Está preparado para una primera ronda de pentest. No sustituye una certificación ISO 27001 / SOC 2 ni un informe de pentest externo firmado.

1. Alcance y metodología

  • Incluye: aplicación Next.js (CourtManager Pro), APIs, autenticación, autorización por equipo, RLS Supabase, cabeceras HTTP, rate limiting, configuración Vercel Production.
  • No incluye: auditoría física, cuentas personales de operadores, red corporativa del club, laboratorio de pentest de terceros, procesos ISO.
  • Método: revisión de código en main, migraciones RLS, configuración de entorno y despliegue Production (agosto 2026).

5. Hallazgos residuales (opcionales / fase 2)

No hay hallazgos críticos abiertos. Lo siguiente es mejora enterprise o evidencia contractual:

ÍtemRiesgoNota para TI
SSO corporativo (Microsoft Entra ID / Azure AD) MEDIO Exigencia habitual de TI de club grande; no bloquea piloto con cuentas Supabase.
WAF perimetral (Cloudflare / Vercel Firewall) BAJO–MEDIO Capa extra ante bots; el rate limit de login ya mitiga fuerza bruta.
CSP sin unsafe-eval BAJO Nota típica en informes; ligado al runtime de Next.js.
Checklists en localStorage → base de datos BAJO Integridad multi-dispositivo; no es bypass de autenticación.
Pentest externo formal + informe firmado PROCESO Evidencia contractual; el producto ya está preparado para la prueba.
ISO 27001 / SOC 2 FUERA DE ALCANCE Programa de compliance aparte (meses + auditor externo).

7. Configuración operativa (Production)

Entorno Production
  • NEXT_PUBLIC_DEMO_MODE=false
  • UPSTASH_REDIS_REST_URL / TOKEN
  • CRON_SECRET obligatorio
  • Supabase URL + anon + service role reales
Preview / Development
  • NEXT_PUBLIC_DEMO_MODE=true (demos comerciales)
  • No usar como fuente de verdad de datos reales
  • Staging recomendado para pentest (no prod sensible)

8. Recomendaciones a TI

  1. Aceptar el nivel actual para piloto / operación controlada del club.
  2. Si se exige política corporativa de identidad: planificar SSO Entra ID (fase 2).
  3. Para evidencia contractual: encargar pentest externo en staging (caja gris) y adjuntar este informe.
  4. Opcional: activar WAF en el edge (Cloudflare o Vercel Firewall).
  5. Mantener DEMO_MODE=false y secretos rotados fuera del control de código.
Premisa: la seguridad al 100 % no existe en ningún sistema conectado a Internet. Este documento describe controles reales verificables y residuales conscientes, no una garantía de impenetrabilidad.
